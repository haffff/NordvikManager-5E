# Fifth Edition (SRD) addon for NordvikManager

Character, item and monster cards, actions and settings for playing fifth edition games in NordvikManager.

## Monsters

**5E Create → Create Monster Card** (or right-click the map → Add → Monster) lists the monsters of the game's
Bestiary sources and homebrew, and creates a filled-in monster card from one; from the map it also places the
token.

## Tokens

Character and monster tokens show an HP bar and the name, the SRD conditions (plus Concentration) picked in the
token's icon picker, and the icons of the character's counters: in the Counters tab a counter can have a token icon,
shown while it's active or while it has uses left. `addon_files/Resources/token_character.json` and
`token_monster.json` are generated by `pnpm tokens:build` (scripts/tokens); a token gets its parts when it's
placed, so tokens placed before a change keep their old parts.

## Homebrew

The GM can make the game's own items, spells, feats, languages and monsters in **5E Settings → 5E Homebrew**. They are
saved in the game (resources `dnd5e_<kind>_homebrew`) and always offered next to the configured sources. The view
exports everything as one file in the addon's data format (the same shape as the files in `data/`), which can be
imported into another game or hosted and added as a source, and imports such files.

## Rebuilding the data

The files are generated from source data in the same JSON format, keeping only entries flagged as SRD:

1. Put the source data files into `tmp-data-to-process/`. That folder is gitignored and **must never be
   committed**: most of its content is not openly licensed.
2. `pnpm srd` writes the SRD-only extract and `REPORT.md` (what is SRD, per file and section) to
   `tmp-data-to-process/_srd/`.
3. `pnpm srd:build` writes `data/srd-5.1/` and `data/srd-5.2/`: one edition each, book references removed,
   links to content not shipped turned into plain text, and the license in every file's `_meta`.

## Development

- `pnpm test` runs the data scripts' tests and the cards' logic tests (`node --test`).
- `pnpm run pack` builds every card and packs the addon.

## Releasing

1. Bump `version` in `addon_files/info.json` and merge it as usual.
2. Run **Actions → Release → Run workflow**.

The workflow packs the addon, checks that the zip's `info.json` matches, and publishes a GitHub Release (tag `<version>`, asset `nm_5e_<version>.zip`). It refuses a version that is already released. The registry ([NordvikManager-Addons](https://github.com/haffff/NordvikManager-Addons)) picks the new version up in its daily sync pull request.
